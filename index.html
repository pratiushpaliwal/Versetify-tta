Test-Time Adaptation, Live: State vs. Weights

An interactive explainer for the DataForge 2026 × Pathway track. Audience: ML students/engineers who know what a matrix multiply and a gradient step are, but have not yet seen fast-weight / Hebbian memory. Prerequisites: linear algebra basics, one pass of gradient descent.
The one-sentence claim: a system can acquire a new input→output rule from a handful of demonstrations by additively accumulating a bounded matrix of state at inference time — zero gradient steps, zero backward passes — and this works well until the number of distinct patterns it must hold exceeds the dimensionality of that state, at which point recall degrades through cross-talk, not through "running out of layers."

Step through it: learn a rule with no gradient at all LIVE COMPUTATION

A small "world" of K colors lives in D-dimensional vectors. A hidden rule π maps every color to another color (e.g. red→blue). You are shown M demonstration pairs of (color → π(color)). Instead of training a network, the system keeps one matrix W and, for every demonstration, adds the outer product W += v·kᵀ. That's the entire "learning" step — literally one line of addition per example, repeated. This is the additive, per-demonstration state update that BDH-CQ's contextual memory generalizes (see Tab 4).

The limitation: capacity is bounded by D LIVE COMPUTATION

A linear associative memory built from outer products can store as many orthogonal patterns as it has dimensions. Push more distinct colors K into a fixed dimension D and the key vectors stop being separable — retrieval starts confusing colors that were never confused when K ≤ D. This is a textbook property of Hebbian / fast-weight memories (Schlag & Schmidhuber's "fast weight programmers" line of work; also the "special case" BDH-CQ's paper describes for additive per-demonstration state, see Tab 4) — not a bug, and not something more training data fixes, because there is no training here.

D = 4
Sweeps K = D → 3×D at full coverage (M = K), using freshly sampled random keys each trial, and reports mean top-1 retrieval accuracy.
Common misconception: "the system just needs more demonstrations." More demonstrations don't help once K > D — every color is already being taught, the problem is that D-dimensional space can't keep K non-orthogonal directions apart. The fix in real systems is a bigger state (more dimensions / more attention heads), which is exactly why architectures care about state width, not just depth.

Here the exact same task (recover π from M demonstrations, evaluate on a new grid) is solved a second way: a small softmax classifier is trained on the demonstration pairs with real gradient descent, computed live in your browser. This is the "optimization route" the track brief attributes to HRM/TRM-style ARC solvers: demonstrations become training samples, and the system needs a backward pass before it can be evaluated on an unseen task. Where this shows up in BDH and BDH-CQ REPORTED RESULTS, PRIMARY SOURCES

BDH: attention reformulated as Hebbian synaptic memory

Dragon Hatchling (BDH) is Pathway's post-Transformer architecture: a scale-free network of locally-interacting "neuron" units whose attention mechanism is derived from first principles as a Hebbian, synapse-level update rather than a dense query–key–value matrix multiply over all pairs of tokens[1]. The paper reports that BDH follows Transformer-like scaling laws and is competitive with GPT-2 at matched parameter counts (10M–1B) on language and translation tasks, while exposing sparse, largely monosemantic neuron activity (on the order of ~5% of neurons active at a time in reported runs) and a scale-free, heavy-tailed connectivity pattern[1]. The GPU-friendly formulation (sometimes called BDH-GPU) is built from ReLU/low-rank transformations combined with linear attention — the track brief is explicit that this should not be read as an SSM in the Mamba sense, and this explainer does not make that claim.

What's actually changing: in BDH, the quantity that plays the role of "recurrent state" is synaptic strength between neuron-particles, updated by activity as the model reads a sequence — the same outer-product/Hebbian mechanism you just ran by hand in Tab 1, just embedded inside a much larger trained network rather than a hand-built toy memory.

BDH-CQ: in-context learning with recurrent latent reasoning

BDH-CQ extends this idea into a reasoning system. Its own paper frames it as combining in-context learning with recurrent latent reasoning: inputs shown at inference time continuously update the model's recurrent memory, and the model then iterates in a high-dimensional latent space to answer a query, without generating a verbalized chain of thought[2]. On the public ARC-AGI-1 evaluation set, a 150-million-parameter configuration reaches 29.5% pass@2 at a computed inference cost of about $0.0007 per task, which the authors present as a new point on the cost–accuracy Pareto frontier for that benchmark rather than a new accuracy record in isolation[2][3].

This is exactly the "counterexample" the track brief describes under Test-Time Adaptation: BDH-CQ is not shown the evaluation task's demonstrations during training, and it performs no parameter update at inference — adaptation happens entirely inside the recurrent state that accumulates as demonstrations are read, mirroring the additive mechanism in Tabs 1–2, not the gradient-based mechanism in Tab 3.

The optimization route: HRM and TRM

The Hierarchical Reasoning Model (HRM) uses two coupled recurrent modules — a slow "planning" module and a fast "detail" module — trained end-to-end with roughly 1,000 examples per task family, and its paper reports that it outperforms much larger chain-of-thought models on ARC-AGI and on Sudoku/maze benchmarks despite using only about 27 million parameters[4]. The Tiny Recursive Model (TRM) simplifies this to a single small weight-tied network that recursively refines a latent state and an answer over a fixed number of steps; its paper reports 45% test accuracy on ARC-AGI-1 and 8% on ARC-AGI-2 with about 7 million parameters, exceeding several much larger LLMs on the same benchmark[5]. A related 2025 paper studies test-time adaptation strategies for TRM directly — comparing full fine-tuning, embeddings-only tuning, and LoRA-style adaptation on the ARC-AGI-1 checkpoint — which is squarely an optimization-route approach: every strategy it compares still requires a gradient computed against the specific evaluation task[6].

Explain it back

Before moving on, write (for yourself — nothing is uploaded) one or two sentences answering: why does the fast-weight memory in Tab 1 count as "test-time adaptation" even though no weight in any neural network ever changes? Then check your answer against the model answer below.

Reveal a model answer

Because "adaptation" doesn't require weights to move — it only requires the system's output to change in response to new information. The matrix W in Tab 1 is not a trained parameter; it's part of the recurrent state, reset for every new task and rebuilt from that task's own demonstrations. The rule (π) the system ends up implementing is different every time you change the demonstrations, without a single gradient step — which is precisely what "adaptation happening in recurrent state rather than in weights" means in the BDH-CQ paper.

Sixty-second self-test

Set K=6, D=4, full coverage, cyclic rule in Tab 1. Predict — before clicking "Learn" — whether accuracy will be closer to 100% or noticeably lower, and why. Then run it and see if you were right. If you predicted "noticeably lower" because K > D, you've correctly applied the capacity limit from Tab 2.

Limitations, scope, and what this artifact is not

  • The Tab 1–3 memory and classifier are small, hand-built toy systems chosen to make one mechanism visible. They are not BDH, BDH-CQ, HRM, or TRM, and are not claimed to reproduce their numbers.
  • Retrieval in Tab 1 uses nearest-neighbor decoding against the known key set for readability. Real fast-weight / linear-attention systems typically decode through a learned readout, not an explicit nearest-key search — this is a pedagogical simplification, stated here rather than hidden.
  • The capacity sweep in Tab 2 uses uniformly random keys, not learned or structured embeddings; real systems can partially mitigate cross-talk through learned key structure, which this toy does not model.
  • BDH-CQ's ARC-AGI-1 result (29.5% pass@2) is a cost-efficiency frontier point, not the highest accuracy available on that benchmark — larger, more expensive systems score higher, as the primary paper itself states.
  • HRM's originally reported advantage has been partly contested by later mechanistic-analysis work showing failures on trivially simple puzzles under certain conditions; this explainer cites that critique rather than omitting it.
